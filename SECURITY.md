# Security Policy

Emoji Engineering is a markdown-first collection, not a hosted service.

The main security concern is preventing public examples, issues, or pull requests from exposing private data, private screenshots, credentials, or copied assets.

## Supported Scope

Security reports are in scope when they involve:

- examples that expose private data
- diagrams copied from private or proprietary material
- contributor guidance that encourages leaking credentials or account data
- unsafe instructions around screenshots, tokens, cookies, passwords, or private exports
- accidental inclusion of sensitive data in examples

Out of scope:

- general disagreements about diagram taste
- source posts that are already public
- issues in third-party platforms such as GitHub, X, Slack, or browser vendors

## Reporting a Vulnerability

Do not open a public issue for a private security report.

Use GitHub's private vulnerability reporting if it is enabled for this repository. If it is not enabled, contact the maintainer privately through GitHub.

Please include:

- affected file or workflow
- what private data or account action is at risk
- steps to reproduce
- suggested fix, if known

## Handling Expectations

The maintainer will review security reports as maintainer capacity allows.

Accepted fixes should keep the project safe to browse, copy, paste, and remix.
