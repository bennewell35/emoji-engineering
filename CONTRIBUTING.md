# Contributing To Emoji Engineering

Thanks for helping make tiny diagrams more useful.

## What To Add

Add diagrams that help builders communicate a system, workflow, status, loop, checklist, product idea, metric, or internet-native artifact.

Strong contributions usually fit one of these categories:

- AI agents
- Product workflows
- Engineering systems
- Fitness / health data
- Bookmark Maxxing
- GitHub / open source
- Launch checklists
- Flags / pixel art
- Founder updates
- Debugging
- Data viz
- Architecture
- Growth loops
- Decision-making
- AI systems
- Internet art

## Diagram Rules

- Keep diagrams copy-pasteable.
- Prefer 3 to 9 visual steps.
- Use code fences with `text` for diagrams.
- Add one short sentence explaining the use case.
- Keep emoji choices readable on light and dark backgrounds.
- Avoid diagrams that require custom fonts or exact platform rendering.
- Do not copy viral posts, private diagrams, brand assets, logos, or copyrighted art directly.
- Credit inspiration when it materially shaped the idea.

## File Format

Add new diagrams to the matching file in `examples/`.

Use this format:

````markdown
## Diagram Name

```text
emoji diagram here
```

One short sentence explaining where to use it.
````

If a diagram does not fit an existing category, propose a new category in the pull request description.

## Quality Bar

A good Emoji Engineering diagram should pass this test:

- Can someone understand the shape in five seconds?
- Can someone paste it into a README, issue, launch post, or chat without editing?
- Is it original enough to belong here?
- Does it feel useful instead of only decorative?

## Pull Requests

Small pull requests are preferred. One category or one clear set of related diagrams is easier to review than a large mixed batch.

Before opening a pull request:

- Check spelling.
- Preview the markdown.
- Make sure the diagram renders as plain text.
- Confirm the diagram is yours to contribute.
