# Governance

Emoji Engineering is currently a maintainer-led open-source collection.

## Maintainer

- Ben Newell (`@bennewell35`)

## Project Direction

The project is copy-paste first.

The current priority is:

1. Useful diagrams.
2. Clear categories.
3. Reusable templates.
4. Strong examples.
5. Source attribution.
6. Lightweight tooling only when the workflow is proven.

This is intentionally not an app yet.

## Decision Rules

Contributions are more likely to be accepted when they:

- make the collection easier to use
- improve attribution
- add diagrams others can copy
- improve templates or category structure
- keep the repo lightweight
- help builders communicate systems, launches, workflows, or status

Contributions are less likely to be accepted when they:

- add broad product scope too early
- require a runtime, account, or hosted service
- copy someone else's post or artwork directly
- add diagrams that are only decorative
- duplicate existing examples
- make the repo harder to browse or paste from

## Maintainer Authority

The maintainer has final decision authority on scope, releases, contribution acceptance, and moderation.

This may change later if the project gains regular contributors.

## Release Model

For now, changes land through normal pull requests into `main`.

No semantic versioning is promised yet. Tags can be added once the collection stabilizes.
